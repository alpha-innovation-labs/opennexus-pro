System Explainer

This map shows Nexus TUI Awesome (v0.2.47) as an isometric city of 8 interconnected buildings on a pnpm monorepo grid. Each tower represents a package or app, with height proportional to architectural importance.

Control Flows (blue)

TUI → Herdr: runApp.ts orchestrates agent sessions through runHerdr.js (packages/herdr/src/core). The resolveBundledExtensionFactories.ts resolves extension factories based on CLI args and feature flags.

Extension Core → TUI: Extensions register via registerBundledExtensions with feature-flag gating (tron, slash-menu, hotkeys). Each extension (notify, auto-update, web-search, subagents, etc.) is registered through the @earendil-works/pi-coding-agent ExtensionAPI.

Extension Core → Factory: Feature flags gate workflow creation. @nexus/feature-flags controls which extensions are active, which flows into Factory's createWorkflow/addStep API.

Data Flows (green)

Herdr → Factory: Workflow execution results flow back via runWorkflow (packages/factory/src/engine/runner.ts). Steps execute through stepExecutor.ts and templateResolver.ts.

Observability → TUI: Startup profiling events from logRunAppPhase (packages/observability/src/startup-profile) track every phase of runApp() execution. wrapExtensionEventHandler instruments all extension calls.

Herdr → Pi Platform: Settings management flows through applyNexusSystemPromptPatch and pruneLoggedOutEnabledModels (packages/pi-platform/src/settings).

Payload Flows (orange)

Factory → Herdr: Workflow commands execute as agent operations via runFactoryCommand → startHerdrAgent. Agent operations include promptHerdrAgent, sendTextToAgent, splitPaneRight, runCommandInPane.

TUI Kit → TUI: UI components (markdown-preview, modal, shortcuts) are injected into the TUI via recordRegisteredShortcut and other TUI Kit exports.

Config Flows (purple)

Nexus Runtime → TUI: applyNexusConfigPatch reads readNexusUserConfig and applies patches. normalizeUsageStartupArgs normalizes CLI args.

Pi Platform → TUI: 8 patches applied at startup: applyStartupUpdateSilencePatch, applyStartupChangelogSilencePatch, applyStartupHelpSilencePatch, applyPromptTemplateArgAppendPatch, applyModelChangeDisplayPatch, applyHotkeysCommandPatch, applyToolExecutionSpacingPatch, applyWorkingLoaderElapsedPatch, applyInlineImageOverlayPatch, applyNexusSystemPromptPatch.

Agent Flows (pink)

Extension Core → Herdr: Subagent tools (startHerdrAgent, promptHerdrAgent, sendTextToAgent, waitAgent, stopAgent) are exposed via the subagents extension. Web-search tools (registerWebSearchExtension) provide webFetchTool through crawl4ai and Jina fetch.

Extension Core → TUI: Tron tool-wrapping (createTronToolWrappingExtensionApi) groups tool executions. Notify extension sends system notifications via OSC escape sequences or Windows toast.

Extension Inventory

Core extensions (packages/extension-core/*/): auto-update, cmux, console-table-printer, context-usage, exit-message, fff, hotkeys, local-image-reader, neo-editor, notify, observations, slash-menu, startup-hero, subagents, system-prompt, tron, web-search.

Other packages: feature-flags, mini-apps (tetris!), nexus-runtime, observability, pi-platform, tui-kit.

Key Source Files

apps/tui/src/runtime/runApp.ts — Single app entry point for dev and release modes. Orchestrates startup phases, extension registration, and delegates to @earendil-works/pi-coding-agent.

packages/herdr/src/index.ts — Agent orchestration library: workspaces, tabs, panes, agents. Core primitives: runHerdr, drill, resolveJustDevBinary.

packages/factory/src/index.ts — Programmatic workflow YAML API: create, edit, query, validate, save/load/delete, and execute workflows.
